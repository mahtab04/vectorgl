01 / DIRECT DRAWING

A shape is a good place to start.

Initialize Canvas after making the OpenGL context current. Use framebuffer pixel dimensions for each frame. Drawing state is explicit and save/restore scopes local changes.

canvas.cpp 
// Inside your OpenGL frame.
canvas.beginFrame(fbWidth, fbHeight);
canvas.setFillColor(vectorgl::Color::hex(0xA6E35C));
canvas.fillRoundedRect(24, 24, 280, 140, 18);
canvas.setFillColor(vectorgl::Color::White);
canvas.fillCircle(164, 94, 36);
canvas.endFrame();
02 / RETAINED OBJECTS

Keep your visual objects around.

Create nodes once. Change properties as input arrives. Parent-child transforms and z-order describe the composition; Scene picking supports interaction.

scene.cpp 
// Create once, then update persistent objects.
vectorgl::Scene scene(canvas.renderer());
auto card = scene.roundedRect(24, 24, 280, 140, 18);
card->setFill(vectorgl::Color::hex(0xA6E35C));
card->setPosition(80, 60);

// During an active Canvas frame.
scene.render();

03 / INPUT AND CONTROLS

From a button to a workspace.

Context owns registration and routing. Controls own their registered subtrees; Context must outlive them. Set the theme's font path before text painting. Forward host events explicitly, and paint UI inside an active Canvas frame.

controls.cpp 
// Context outlives the controls it owns.
vectorgl::ui::Context ui;
vectorgl::ui::ButtonOptions options;
options.label = "Save document";
options.onActivated = [] { /* Application save hook. */ };
vectorgl::ui::Button save(ui, {}, options);
ui.setBounds(save.id(), {24, 24, 180, 44});

// Forward host input; paint inside a Canvas frame.
ui.dispatch(event);
ui.paint(canvas, viewport);

Keep domain work in your application.

Native Save chooses a path; your application serializes its document and updates dirty state after successful I/O. The integrated workspace demonstrates those hooks.

Work through one idea at a time.

Copyable examples for paths, text, SVG, clipping and animation.

Build on explicit contracts.

  • Keep graphics resources alive only while their OpenGL context is valid.
  • Cache fonts, images and persistent scene nodes outside the render loop.
  • Drain host events under the file-dialog modal barrier before restoring input.
  • Use stable IDs for filtered collections and document operations.
  • Drive idle UI painting from invalidation and timer deadlines.
Text and accessibility scope

Editing is left-to-right and codepoint based. Complex shaping, bidi, IME composition, grapheme editing and OS accessibility bridges remain separate work. Read the migration gates ↗ before replacing those capabilities in an existing application.
