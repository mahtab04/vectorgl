THE BIG PICTURE

A shared renderer. Clear responsibilities.

VectorGL is a C++20 library for GPU-backed vector graphics and application UI. Draw directly with Canvas, retain visual objects in Scene, or compose controls through UI Context. These layers can coexist in the same frame.

You own the host.

Create the window and OpenGL context, forward input and manage presentation. VectorGL owns drawing resources and the controls you compose through its public API.

Keep the frame loop explicit.

  1. Process input

    Forward host events to UI. Offer unconsumed input to scene/application actions.

  2. Advance state

    Update application state, animation and UI timer deadlines.

  3. Draw when needed

    Begin the Canvas frame, submit the scene and UI, then end the frame.

  4. Present

    Swap the host's buffers. Release graphics resources before destroying the GL context.

Start with a complete program.

Use a C++20 compiler, CMake 3.21+ and an OpenGL 3.3 driver. VS 2026 requires CMake 4.2+. Linux host builds need GLFW's window-system development packages.

Terminal 
git clone https://github.com/mahtab04/vectorgl.git
cd vectorgl
cmake --preset workspace
cmake --build --preset workspace --target vectorgl_ui_editor_workspace

Visual Studio executable: build/workspace/example/Debug/vectorgl_ui_editor_workspace.exe. With Ninja: build/workspace/example/vectorgl_ui_editor_workspace.

Profile What you build
library All library modules; no tests, examples or apps.
developer Library modules and CPU tests.
workspace UI examples and CPU tests.
full Examples, Flow Studio, app tests and GPU checks.
core Explicit graphics-only build, without UI/host/dialog modules.

See the complete build guide ↗ for MinGW, toolchain selection, system dependencies and offline builds.

Link what your application uses.

CMakeLists.txt 
include(FetchContent)
FetchContent_Declare(vectorgl
  GIT_REPOSITORY https://github.com/mahtab04/vectorgl.git
  GIT_TAG 22975c2e4a252e196c19616028f390e6d2fee3ab
)
FetchContent_MakeAvailable(vectorgl)

target_link_libraries(my_app PRIVATE vectorgl::ui)

For an installed SDK, request its components explicitly:

Installed SDK 
find_package(vectorgl CONFIG REQUIRED COMPONENTS ui glfw dialogs)
target_link_libraries(my_app PRIVATE vectorgl::glfw vectorgl::dialogs)

VectorGL's targets are static libraries. UI links core; host/dialog targets link UI and core. Dependencies can still be shared when supplied by a parent project. Building the native dialog backend does not open a dialog; Linux Zenity is needed only when using that backend at runtime.
